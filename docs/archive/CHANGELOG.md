### OPT-001

**工具命令与统一注册表（已完成）。** 提出、复评、完成/核验及归档日期：2026-11-06（Asia/Shanghai）。来源：设计模式与项目架构讨论；随后用户明确要求实现 OPT-001/002、新增版本工具并使用真正 MCP。

实施前问题：tools/registry.py 分开维护 TOOL_SCHEMAS 和名称分发，只有一个时间工具，暂未出现维护负担。

- 原方案：小型 Tool dataclass 关联 schema 与执行函数，字典按名称分发，描述和执行从同一来源产生；JSON 解析在接入边界，工具负责具体参数。MCP 在 tools 适配，Agent 不维护服务器名单。
- 原评估：可行性高，可复用执行入口；当前优化度低，工具增多后为中，可减少漏注册和描述/执行不一致。成本小；风险为无职责继承层或改变错误语义。
- 原实施条件：新增第二个实际工具或首次 MCP 接入时同步实施，资源关闭和调用上下文随真实需求补齐。
- 原验收：多工具描述/执行一致、重名明确处理；未知工具、无效 JSON 和参数错误可预测；结果进入完整轮次，时间工具兼容。
- 实施前复评：保留为扩展首选候选，等待第二个运行时工具；Codex 开发技能不算触发。最小方案为 Tool 数据类及字典，保持 JSON 契约，使用测试第二工具验证注册；主要影响 tools，无需改变 Provider、渠道、数据库或公开 Agent API。tradeoff 为少量注册结构换一致性，不引入插件扫描/继承体系；通过工具及端到端测试和三项项目检查，可回退工具模块与测试，无数据迁移。
- 本轮复评：版本与天气满足触发条件，维护收益为中（未测量性能比例）。真正 MCP 的额外依赖与异步生命周期为独立 OPT-016 的中等成本，不能沿用原注册表“小改动”估算代表全部接入。
- 实际结果：Tool 保存 MCP 描述、客户端与本地上下文标记；服务器发现结果同时派生模型 schema 和执行入口，移除运行时代码中独立的 TIME_TOOL 描述。参数按 JSON Schema 校验，注册时拒绝重名；支持结构化和文本结果。版本上下文只传本地服务，weather 只暴露允许工具。
- 影响/回退：Agent 仅改用注册表实例并释放资源，Provider、SQLite 表结构和公开入口不变。回退注册表及 MCP 接入需一起恢复 Agent 调用和依赖声明；保留数据库与本机配置文件。
- 验收证据：[registry.py](../../ai_butler/tools/registry.py)、[test_mcp.py](../../tests/test_mcp.py)、[test_core.py](../../tests/test_core.py) 和 test_app.py；94 项测试、Ruff、Pyright 通过，真实 stdio 时间/版本调用通过。高德联调另见 OPT-016。

### OPT-002

**通用聊天命令分发（已完成）。** 提出、复评、完成/核验及归档日期：2026-11-06（Asia/Shanghai）。来源：设计模式与架构优化讨论；用户随后要求实施并新增版本查询。

实施前问题：core 处理 `/model`，CLI 处理终端命令，分工合理；只有一个跨渠道业务命令。

- 原方案：通用命令增加时，core 使用“命令名 → 处理函数”，返回 Reply；终端退出、帮助及会话交互留在 CLI，不预建命令总线或类层次。
- 原评估：可行性高，已有 IncomingMessage / Reply；当前收益低，多命令后为中。成本小；风险为终端交互混入业务或各渠道重复维护名单。
- 原实施条件：第二个跨渠道命令，例如 M2 中已明确语义的记忆命令。
- 原验收：CLI/QQ 通用行为一致，普通聊天不误判；切换不调用模型、不写历史；失败和旧消息重推不覆盖新选择；CLI 本地命令可用。
- 实施前复评：只有 `/model` 时无需提前抽表，开发技能不算聊天命令；主要改动 core，必要时调整 CLI 放行，无需修改 Provider 或 SQLite。最小方案随第二命令建立处理映射并迁入 `/model`；tradeoff 为增加分发入口与命令名/错误语义维护，不引入总线。验证同一命令、普通聊天、切换失败、旧消息重推及三项项目检查；命令路由可独立回退，无数据迁移。
- 本轮复评/结果：`/version` 满足触发条件，收益为跨渠道一致性，定性为中；Agent 字典分发 `/model`、`/version`，未知斜杠命令返回提示。CLI 本地命令继续在渠道处理，其余交给 Agent；版本查询复用 MCP，不调用模型或写入模型历史，并读取当前会话的模型选择。
- 影响/回退：小规模修改 Agent、CLI 帮助与放行、流程测试；不更改渠道协议、Provider、数据库表或公开 API。可独立撤回 `/version` 路由和对应帮助，恢复原 `/model` 分支；无需数据回滚。
- 验收证据：[agent.py](../../ai_butler/core/agent.py)、[CLI](../../ai_butler/channels/cli/_channel.py)、[test_app.py](../../tests/test_app.py) 与 test_channels.py；CLI/QQ 版本命令、会话切换、未知命令、普通聊天、失败及旧消息重推覆盖，94 项测试、Ruff、Pyright 通过。

### OPT-016

**真实 MCP、版本查询与高德天气（已完成）。** 来源、提出/评估、完成/核验及归档：2026-11-06（Asia/Shanghai）。用户提出新增 get_version，明确选择真正 MCP 协议，随后选择高德官方天气服务并在本机提供 Key；此独立能力范围随 OPT-001/002 同轮实现并归档。

- 问题/方案：原时间函数不是 MCP，也没有外部天气能力。使用官方 Python MCP SDK，在 tools 增加同步/异步适配器与本地 stdio 服务；服务器暴露时间和版本，外部天气经高德 Streamable HTTP 接入，只允许 `maps_weather`。
- 可行性：高，现有模型工具循环可以复用，官方服务支持城市名/adcode 天气查询；已验证 SDK 2.3.0、当前解释器和官方服务互通。
- 优化度：中，新增实际外部只读能力，工具发现与生命周期有统一边界；不宣称性能提升，也不替代上下文预算或运行时 Skill。
- 成本/风险与 tradeoff：中，增加 MCP、AnyIO、JSON Schema 和 HTTP 依赖以及后台事件循环/子进程；比直接 HTTP 天气函数复杂，换取用户要求的标准 MCP 协议与可复用适配。高德受网络、Key 权限、服务限额及天气数据时效约束；模型自动选工具可能漏掉复合请求中的部分任务。整轮预算、结果大小限制和自动重连尚未实现。
- 实施条件/方案：真实第二工具和外部查询需求已明确；以当前 Python 启动 stdio，用 AnyIO portal 持有异步会话，由 registry 发现并校验参数；Key 仅从 Config.options 取得。未配置高德 Key 时不连接远端；发现失败保留本地工具。关闭先等待渠道结束，再释放 MCP 会话/子进程/线程。
