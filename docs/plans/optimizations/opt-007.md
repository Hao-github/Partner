状态：暂缓；提出/更新：2026-11-06（Asia/Shanghai）。来源：设计模式与项目架构优化讨论中的建议，尚未实施。

涉及模块与验证落点：[QQ 网关](../../../ai_butler/channels/qq/_gateway.py)、[QQ 测试](../../../tests/test_qq.py)。

**QQ 网关显式状态对象。** 现有 QQGateway 已用状态变量、停止事件和 match 表达登录、心跳、恢复与重连，不是缺少状态管理。

- 方案：状态转换难以维护时，再评估枚举、转换表或 State 对象；先采用能够消除真实重复的最小表示。
- 评估：可行性高；当前优化度低，复杂状态重复出现时为中。成本中；风险是增加状态类数量或漏掉心跳/恢复转换。
- 暂缓原因/触发：现有实现与测试已覆盖主要流程；不能仅因协议有状态就引入 State 类层次。
- 验收：Hello/登录期限、READY/RESUMED、心跳确认、无效会话、断线重连和关闭行为均有验证；已登录连接不再受初始登录期限限制。
