# OPT-003

状态：暂缓；提出/更新：2026-11-06（Asia/Shanghai）。来源：设计模式与项目架构优化讨论中的建议，尚未实施。

涉及模块与验证落点：[Agent 模型循环](../../../ai_butler/core/agent.py)、[测试依赖替换](../../../tests/helpers.py)。

**内部依赖注入与模型循环边界。** Config 和消息处理回调已通过参数传入；现有模型循环测试仅需替换一个工厂，当前 Agent 规模可控。

- 方案：必要时让内部模型循环显式接收 Provider 与工具执行器，Agent 保持统一公开入口并在内部组装；只在出现独立职责时拆出模块。
- 评估：可行性高；当前优化度低，复杂替换或复用场景下为中。成本中；风险是增加转发层、公开多套运行入口，或把工厂/模型缓存职责分散。
- 暂缓原因/触发：单个工厂 patch 已满足测试；待共享工具上下文、资源生命周期或独立复用使边界确有价值后重评。
- 验收：内部循环可用显式测试依赖执行；生产仍由 Agent 启动；模型缓存、选择、失败处理和完整轮次不变；模型 mock 仅在 tests。

2026-11-06 补充：[OPT-017](../../archive/CHANGELOG.md#opt-017) 已完成 ModelService 和 ChannelService 提取；模型/工具循环仍留在 Agent。本项继续跟踪独立循环与显式依赖注入，尚未达到独立复用触发条件，不重复创建服务提取任务。
