# OPT-008

状态：暂缓；提出/更新：2026-11-06（Asia/Shanghai）。来源：设计模式与项目架构优化讨论中的建议，尚未实施。

涉及模块与验证落点：[会话存储](../../../ai_butler/storage/sessions.py)、[事务测试](../../../tests/test_storage.py)、[记忆一致性设计](../../design/capabilities.md#长期记忆及数据一致性)。

**仓储与工作单元抽象。** SessionStore 当前直接封装查询和事务；完整 Repository / Unit of Work 尚未引入，也不是当前必需能力。

- 方案：长期记忆等多个持久化用例出现后，若确有共享事务与查询规则，再抽取有实际职责的存储接口；保持连接和事务所有权清楚。
- 评估：可行性中，需结合新数据契约和迁移；当前优化度低，多用例协作后为中。成本中；风险是通用 CRUD 包装、重复抽象或破坏原子提交。
- 暂缓原因/触发：现有 SessionStore 已满足需求；与 roadmap M2 的记忆变更一起评估，不提前建立通用持久化框架。
- 验收：需要原子提交的变化共用事务，失败整体回滚；不跨线程共享连接，不持有写事务等待网络；旧库迁移和缓存重推可验证。数据库事务不被描述为跨平台恰好一次发送保证。
