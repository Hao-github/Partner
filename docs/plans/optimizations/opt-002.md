# OPT-002

状态：候选；提出/更新：2026-11-06（Asia/Shanghai）。来源：设计模式与项目架构优化讨论中的建议，尚未实施。

涉及模块与验证落点：[业务命令](../../../ai_butler/core/agent.py)、[CLI 交互](../../../ai_butler/channels/cli/_channel.py)、[流程测试](../../../tests/test_app.py)。

**通用聊天命令分发。** 目前 core 处理 `/model`，CLI 处理终端命令，分工合理；只有一个跨渠道业务命令。

- 方案：通用命令增加时，在 core 用“命令名 → 处理函数”分发，处理器返回 Reply；CLI 的退出、帮助呈现和终端会话交互继续留在渠道。使用函数即可，不预建命令总线或类层次。
- 评估：可行性高，已有统一 IncomingMessage / Reply；当前优化度低，多条通用命令时为中。成本小；风险是将终端交互混入业务，或在各渠道重复维护通用命令名单。
- 实施条件：新增第二个跨渠道业务命令，例如已明确语义的记忆命令；与 roadmap M2 等实际用例结合。
- 验收：CLI/QQ 的通用命令行为一致；普通聊天不误判；模型切换仍不调用模型、不写模型历史；失败及旧消息重推不覆盖新选择；CLI 本地命令继续可用。
