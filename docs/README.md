# GPTPartner 文档

本目录记录项目的架构、能力设计和运行方案。当前基线为个人文本聊天 MVP；设计中的模块、命令和文件只有在对应实现合并后才成为可用功能。

## 状态约定

| 状态 | 含义 |
| --- | --- |
| 已实现 | 有对应源码和验证，可按使用说明运行 |
| 待实现 | 已记录方案和边界，当前程序尚不支持 |
| 待决策 | 需要具体任务、部署环境或实际负载后才能选择 |

已实现：CLI、QQ 官方机器人 C2C 文本、OpenAI / DeepSeek、会话历史、会话模型切换、本地时间工具、回复缓存及有限重试。

待实现：输入上下文预算、独立补发、Linux 停止信号处理、常驻部署、SOUL.md 加载、长期记忆、MCP、Skill、定时任务和睡梦整理。Grok、Gemini、Telegram、WhatsApp 尚未接入。

## 文档维护

- 架构完整性以职责、依赖、数据一致性、资源释放、失败恢复和验证条件衡量；新增目录或设计模式本身不代表能力完成。
- 改动模块边界时更新架构设计；新增能力时更新能力设计和验收状态；实际行为变化记录到 CHANGELOG。
- README 保留用户入口和操作说明，架构文档作为内部设计的主要说明，HANDOFF 保留环境与进度，避免复制整份设计。
- 规划中的类、文件、命令和配置必须标明待实现，不提前创建空模块或无职责的包装层。
- 对话产生的优化想法在优化计划中合并记录并评估，未完成项保留在 docs；完成后将完整条目归档到 CHANGELOG，计划保留原编号、已完成状态与归档链接。具体字段和流转规则见 [优化计划](optimization-plan.md)。
- 文档示例只用占位值；凭据、真实用户标识和私人记忆不进入文档或 Git。
